## Lessons

### 1. A claim-source file in `touches` invalidates every doc that claims it

**This was already documented.** `.wiki/core/18-knowledge-capture.md:50` states it, names `AGENTS.md`, names both claiming docs (09 and 12), and prescribes the remedy (`python scripts/wiki_claims.py update`). The plan's Phase 2 read that file — and cited § Sync & Versioning and § Parcel Pipeline, **never `:50`**.

**The gap is a reading discipline, not missing knowledge.** When any file in `touches` is a Grounded Claim *source*, Phase 2 must enumerate the claiming docs and put them in the write set (or record why the re-stamp is out of band). Adding a second copy of the rule would violate one-canonical-home; the fix belongs in how the inventory is performed.

### 2. Never edit repo files in place with PowerShell text cmdlets — *a recorded rule, re-violated*

The orchestrator edited the plan's State & Gates with `(Get-Content -Raw) … | Set-Content -Encoding utf8`. On PowerShell 5.1 that is **destructive**: `Get-Content` decodes UTF-8-without-BOM as **cp1252**, then `Set-Content -Encoding utf8` re-encodes the mojibake — **double-encoding every non-ASCII character** and adding a BOM.

- **Detected** immediately by byte inspection (first bytes `EF BB BF`; `read` rendered `â€”` for `—`).
- **Repaired losslessly**: .NET's cp1252 table maps all 256 byte positions (including the five undefined in classic Windows-1252, which it maps to the C1 controls), so the transform reverses exactly — read as UTF-8, encode to cp1252, decode as UTF-8. Verified by a strict-UTF-8 round trip and a non-ASCII inventory (411 chars restored intact).
- **⚠️ This rule already existed and was violated.** `.devops/rules/process-lessons.md:34` — *"[2026-09-17] Never round-trip a file through PowerShell text cmdlets"* — records **the same mechanism** (PS 5.1 reading BOM-less UTF-8 as ANSI, mojibake-corrupting six skill files in `T1-E4.01`), and `:70` records the BOM half again. **No new knowledge entry is added** — the register has one canonical home per rule and sits near its ~25-entry cap; a duplicate would be the one-way ratchet it warns about.
- **What the repeat proves:** a prose rule is not a control. The fix is a **mechanical guard** — a `git diff` BOM/EOL check in `validate.yml` — and that is the open item below, not a fifth restatement.

### 3. This parcel was stopped four times, and every stop was scope — never design

`touches` went **4 → 10 → 11 → 13**. The design survived 4 revision rounds, 3 independent Phase 6 rounds and 1 Phase 7, and was verified by **16 of 17** Phase 9 commands. Its committed size was **S (1)**; it is a **13-file sync-engine change**. The lesson for the pipeline is that *write-set derivation is the weakest link in the parcel contract* — and it deserves the same determinism the eligibility predicate got.
