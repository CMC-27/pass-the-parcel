# Parked: T1-E2.02 - Split the `check-parcel-prefix.ps1` god-script

> **Origin:** Phase 6 Spaghetti Triage flag in [T1-E1.03](../archive/t1-e1.03-model-binding-propagation-plan.md). Routed, not fixed, by that plan (See-Name-Route, Do Not Fix).

## Problem

`scripts/check-parcel-prefix.ps1` now carries **four** unrelated concerns in one linear pass:

1. Registry parsing (the Model Registry table).
2. Prefix integrity for the PREFIX-LOCKED agents (`parcel*` / `ptp-*`).
3. Skill-embed drift for every `ptp-*` agent (EMBED markers vs `SKILL.md`).
4. Model-binding integrity across six surfaces (live registry, seed registry, frontmatter, `opencode.json`, seed opencode config, file↔row existence).

T1-E1.03 decoupled concerns 2 and 4 into separate passes, but the file remains a single 400+ line script whose name describes only one of its four jobs. Every new binding rule lands in a file named `check-parcel-prefix`, and a satellite reading CI output cannot tell which contract a failure belongs to.

## Proposed action

Extract into `scripts/check-model-bindings.ps1` (binding only: surfaces 1 + 4), leaving prefix + embed integrity in `check-parcel-prefix.ps1`. Wire the new script into:

- `.devops/sync-manifest.yaml` → `portable_files` (so satellites receive it).
- `.github/workflows/validate.yml` → its own step (the current "Parcel prefix integrity" step then covers one concern).
- `sync-architecture.ps1 -Verify` → run both, so a satellite's verification stack matches CI.

## Constraints

- **I/O contract is public.** `MODEL` / `SEED-OC-MODEL` / `OC-MODEL` output lines and the exact failure strings are asserted by the T1-E1.03 verification table; keep them stable or version the change.
- **`-Sync` must stay in one entry point.** Prefix regeneration and embed refresh belong together; do not split `-Sync` across two scripts.
- **Cost of the split:** three new wiring points for one concern — acceptable only because the file's name lies about its contents today. If a fifth concern lands first, split by concern, not by layer.
