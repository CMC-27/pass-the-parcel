# Backlog: T1-E1.06 - No `ptp-*` subagent is reachable on the opencode surface, so MULTI and the batch runner cannot run there

## Theme-Epic: T1 - Parcel Pipeline Machinery, E1 - Model & Config Integrity

**Discovered:** 2026-09-28, running Sprint 13 plan 3 of 9 (`T1-E3.22`, `Agents: MULTI`) — the plan was claimed and promoted, then **halted before Phase 1** because Group A could not be spawned. The claim was released back to the queue (`44dc02b`); no phase content was written.

> Findings 1-3 are one defect (unreachable hidden subagents) observed at three radii. Finding 4 is the documentation half of the same gap: the machinery answers *"which model"* per surface but not *"which topologies are executable here"*.

## What a fix would touch

- `opencode.json` + `.devops/templates/opencode.template.json` — the `agent.<key>` entries for the 7 `ptp-*` and `wiki-verifier`. Three shapes: drop `"hidden": true`, change `"mode"`, or move the definitions to `.opencode/agent/*.md` so the runtime registers them as callable subagents. This is the fork the fix turns on.
- `.opencode/plans/base-context.md` (+ `.devops/templates/base-context.template.md`) — the Agent Topology / runtime-asymmetry note gains a **subagent availability** row beside the existing model-selection one. **Reserved surface** (`PREFIX-LOCKED`) → the fix cascades: `-Sync` re-inlines the prefix into all 9 locked agents, and `check-parcel-prefix.ps1` is bidirectionally tied to the registry ↔ file ↔ config pairing.
- `.devops/skills/pass-the-parcel/SKILL.md` § Agent Topology + `.devops/skills/model-routing/SKILL.md` §3 — same row, cited not restated.
- `.devops/skills/sprint-run/SKILL.md` § 1 Preflight — a **spawnability preflight**: prove the per-plan runner can be spawned *before* the first claim, so a batch halts on a clean trunk instead of after claiming. Same shape as `T1-E3.22`'s green-baseline gap, and the same argument.
- `.devops/rules/agents-and-skills.md`, `AGENTS.md`, `.devops/templates/AGENTS.template.md`, `HOW-TO.md` — the surface caveat, wherever the fleet is described.
- Possibly `scripts/check-parcel-prefix.ps1` — only if the fix changes the agent-file set or the Model Registry rows (the checker asserts key ↔ binding-file ↔ row coverage in both directions).

## Open questions for Phase 3

- [ ] **Expose them, or declare the limitation?** `T1-E1.04` chose *state the asymmetry, halt explicitly* for model binding at run time. Is the same answer right here, or is this simply a wrong flag in a config this repo owns and can fix?
- [ ] **Which flag is actually responsible?** `hidden: true`, `mode: "subagent"`, or the runtime's handling of `"{file:...}"` prompts? The evidence is a single probe pair — confirm the mechanism before editing anything, and re-probe after.
- [ ] **Does a spawnability probe belong in the preflight, or is it a one-off diagnosis?** A preflight that proves the runner spawns is cheap and deterministic; a preflight that proves *every* topology spawns is a second gate. Which one earns its cost?
- [ ] **Does the fix travel?** `opencode.json` and its seed are portable, so a config change ships to satellites; a documentation-only answer needs no `machinery-version` bump. Which one this is changes the release level and the write set.
- [ ] **Is the probe itself worth keeping?** A one-line capability check (`<agent> spawns: yes/no`) has no home today, and `@sprint-run`'s preflight is the only surface that would consume it.

## Why NEXT

It makes the pipeline's **default** topology unusable on one of the two surfaces this repo names, and — if finding 3 holds — takes the whole batch path with it. `OPERATING-PRINCIPLES` sells `MULTI` as the comprehensive path with independent review; a user can plan a MULTI sprint, commit it, and discover the failure only after a claim. That is a V1-honesty defect, not a polish item: the docs promise a capability the surface does not deliver, and the cost lands after work has been committed. Tier it at the next `@sprint-plan` and pair it with `T1-E3.22` — the green-baseline preflight and this spawnability preflight are the same class of gap (a claim that cannot prove it starts from a working base).
