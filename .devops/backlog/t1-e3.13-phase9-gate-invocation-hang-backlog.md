# Backlog: T1-E3.13 - Phase 9 gate invocation can hang the batch runner (and nothing defines a resume)

## Theme-Epic: T1 - Parcel Pipeline Machinery, E3 - Concurrency & Sprint Lifecycle

**Discovered:** 2026-09-22, during a live `@sprint-run` at the GRID-Link satellite (Sprint 13, batch run 2). The `ptp-parcel-fast` runner for `T19-E2.04` hung on `npx vitest`; the subagent was cancelled, leaving the plan in a state the lifecycle does not name and cannot resume.

## Findings

| # | Gap | Evidence | Impact |
|---|-----|----------|--------|
| 1 | **A machinery-owned literal launches watch mode.** `@test-and-deploy` Step 4 instructs `npm test` / `npm run test`. On a Vitest satellite whose `package.json` carries `"test": "vitest"` — the default shape for this machinery's own declared stack (React + Vite + Vitest) — that starts vitest's **watch mode** and never returns. | `test-and-deploy/SKILL.md:30`; GRID-Link `package.json` `"test": "vitest"`; live hang 2026-09-22. | The instruction terminates only when a human or the host kills it. Reachable from `@sprint-run` and from every pre-push. |
| 2 | **The batch path states no invocation hygiene at all.** `ptp-parcel-fast` (v8) says only *"Play `ptp-code-surgeon` inline (Phases 8-9)"* — no one-shot requirement, no timeout requirement — so the runner inherits whatever the satellite's plan wrote. `template-plan.md`'s Phase 9 scaffold names only "Lint clean (exit 0)" / "Build pass (exit 0)". | `ptp-parcel-fast/SKILL.md:26`; `plans/template-plan.md:236-247`. | Two independent hangs, both silent: watch mode (F1), and a multi-minute suite against the executing tool's default timeout — GRID-Link's suite is ~262 files / ~2070 tests, ~150 s. Both present as *"the runner is working"*. |
| 3 | **No defined resume for a runner killed mid-Step-10.** The observed debris is a state the lifecycle never names: plan **body** `Status: PHASE_9`, front-matter `claim_status: CLAIMED`, an **empty** Phase 9 evidence table, **no** `plan:` commit, and a dirty trunk holding the whole write set. The runner's own guard (bottom `Status` already `PHASE_9` → `SKIP`) **blocks the obvious re-spawn**, and the AUTO Gate Evidence Contract is unsatisfied, so neither `SKIP` nor a clean `DONE` is correct. | Live debris 2026-09-22 (`T19-E2.04`): body `PHASE_9` / `claim_status: CLAIMED` / evidence placeholders / 15 files uncommitted / no `plan:` commit. | The host had to **invent** an out-of-contract "resume mode" override to finish the plan. Every future cancellation re-opens the hole — and a cancelled runner is the *expected* consequence of F1/F2. |

> F1 and F2 are the trap; F3 is why it cost more than a retry. One incident, one parcel (precedent: `T1-E3.06` bundled G1-G3).

## What the fix does

1. **F1 - one canonical one-shot invocation.** `@test-and-deploy` names a **non-interactive** invocation and how to derive it (`npm test -- --run` / `npx vitest run` / `CI=true npm test`). A `watch`-shaped script is the failure, not the operator's mistake.
2. **F2 - Phase 9 gate discipline, cited not restated.** `ptp-parcel-fast` and the `template-plan.md` Phase 9 scaffold gain one line: gate commands are **one-shot**, and a gate expected to exceed the executing tool's default timeout must be invoked with an **explicit extended timeout** (or backgrounded and the result read). One home, cited — never restated per skill (Managed Simplicity / `surface-budget.md`).
3. **F3 - a named resume state.** Define the interrupted-run outcome (e.g. `HALT <code>: interrupted mid-Step-10 - resume`) with the host's duty: detect body-`PHASE_9` + `claim_status: CLAIMED` + empty evidence, then continue **Step 10 only** — never re-run Phases 1-8, never fabricate evidence. Stated once in `plan-lifecycle.md`, cited from `ptp-parcel-fast` + `sprint-run`; the runner's `already PHASE_9 → SKIP` guard gains its missing exception clause.
