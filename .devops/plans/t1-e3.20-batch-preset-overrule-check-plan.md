The reader is presence-based, so an absent block reports `authored: None`, never an error. Recorded, not hidden.
- **The reader could fire on the template's own default (resolved by scope).** `template-plan.md` ships `Mode = USER-MANAGED` as its scaffold default, so a plan instantiated from it and left un-set would flag. That is **correct**, not a false positive: the plan's recorded intent genuinely is `USER-MANAGED`, and the batch preset genuinely overrules it. The key is advisory, so a flag is an operator prompt, never a block.
- **An unrecognised authored Mode flags rather than hides (resolved by Q3, fail-safe).** The `complexity` precedent fails **open** on an unknown `triage` (it does not fire the declared signal). This check fails **closed**: any present non-`AUTO` value conflicts, because the risk it guards is a *silent* overrule and the check is advisory — a spurious flag costs one operator glance, a hidden one costs the exact bypass the four gates exist to prevent.
