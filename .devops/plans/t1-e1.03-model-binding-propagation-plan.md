## 1 Phase 1: Expansion & Scoping
**Skill Executed:** `ptp-context-hunter`

**Intent:**
Keep declarative model routing (do NOT remove it). Add two capabilities the pipeline lacks today:

1. **Cross-surface alignment checks.** Today only the live trio is validated (registry ↔ agent frontmatter ↔ `opencode.json`, via `check-parcel-prefix.ps1`). The **seed** surfaces are never checked against each other or against the live surfaces, so a template can ship a registry and a seed config that disagree with each other and with what the template workspace actually runs. Add deterministic validation so every surface that carries a model binding is proven to agree, or fails loudly.
2. **Template → satellite binding propagation.** A model binding chosen in *this* template workspace must be carried to satellites by `@sync-architecture`. Today it is explicitly not: the live registry and `opencode.json` are excluded from the portable surface, while the agent frontmatter that *is* copied keeps the template's model.

**Pre-populated reconnaissance (orchestrator, 2026-09-13 — Phase 3 still re-runs interactively):**

*Binding surfaces that exist today:*

| # | Surface | Role | Live? | Transported? | Validated? |
|---|---|---|---|---|---|
| 1 | `.opencode/plans/base-context.md` → `## Model Registry` | canonical registry | live | **No** | yes (target of check) |
| 2 | `.devops/agents/*.agent.md` / `*.subagent.md` → frontmatter `model:` | VS Code runtime binding | live | **Yes** (`.devops/agents` is a `portable_dir`) | yes (subject of check) |
| 3 | `opencode.json` → `agent.<key>.model` | opencode runtime binding | live | **No** | yes (subject of check) |
| 4 | `.devops/templates/base-context.template.md` → registry table | seed registry (**blank cells**) | seed | yes | **No** |
| 5 | `.devops/templates/opencode.template.json` → `agent.<key>.model` | seed binding (`<your provider/model>` ×11) | seed | yes | **No** |
| 6 | `.devops/templates/AGENTS.template.md`, `SATELLITE-BOOTSTRAP.md`, `HOW-TO.md` | prose describing the routing model | seed/docs | yes | **No** |

*The latent bug (verified by reading, not assumed):* `sync-architecture.ps1:54-58` states the repo-specific surface (`base-context.md`, `opencode.json`, `AGENTS.md`) is **not** copied, and after the portable surface is copied the script regenerates each agent's PREFIX-LOCKED prefix from the **target's own** `base-context.md`. But the frontmatter `model:` line sits *above* the prefix and is copied verbatim from the template. Therefore a satellite that legitimately rebinds its own registry receives template frontmatter and `check-parcel-prefix.ps1` fails **by construction**. Sync cannot detect it either: `Get-ItemHashes` (`sync-architecture.ps1:271-292`) strips frontmatter for `parcel*`/`ptp-*` before hashing, so model drift is invisible to `-Check`.

*Contract tension to resolve in Phase 3:* T1-E1.01 (completed 2026-09-03) concluded *"concrete model binding is satellite configuration in `opencode.json`"*, and KC `.wiki/core/18-knowledge-capture.md` § Agents & Models records **Dual-surface agent binding**. A single propagating source of truth is a third surface unless the design deliberately makes one surface canonical and derives the others. The requirement **partially reverses** T1-E1.01; the reversal must be an explicit recorded decision, not an accidental drift.

**In Scope:**
- A deterministic alignment check covering all six surfaces above, wired into `scripts/` and the `validate.yml` gate set.
- A propagation mechanism so a template-workspace binding choice reaches satellites coherently (registry + runtime + frontmatter agreed on arrival, or an explicit documented reconciliation step).
- Reconciliation of the T1-E1.01 decision and the "Dual-surface agent binding" KC rule with the new propagating-source design.
- `@model-routing` skill update so the rebinding procedure stays the single documented path.
- Seed template updates (`base-context.template.md`, `opencode.template.json`) so a bootstrapped satellite starts aligned.
- Version/state discipline for every touched `.devops/skills/**`, `.devops/templates/**`, `scripts/**` artifact.

**Out of Scope:**
- Removing model routing (explicitly rejected by the user — routing stays declarative per-capability-class).
- Per-agent model *selection* policy or capability-class redesign — the class→model decision matrix in `@model-routing` §2 is not in question.
- Any satellite's local model choice retroactively — propagation defines how a template binding arrives, not that satellites must accept it (acceptance semantics are a Phase 3 question).
- The `wiki-writer` / `wiki-verifier` agents — they carry bindings but have no Model Registry row; whether they gain rows is a Phase 3 question.
- Any change to the `parcel-sprint` / `ptp-parcel-fast` batch behaviour shipped by T1-E3.02.

**Perimeter Notes:**
- This plan **depends on T1-E3.02** (now archived) because it edits the same sync/validator/registry surface that plan just rewrote.
- `SINGLE` topology ⇒ Phase 6/7 are inline self-reviews; the sync-engine change ships without an independent adversarial reviewer (user-accepted at selection).
- Phase 3 must interrogate, at minimum: (a) *what* is the single canonical binding source; (b) whether a template binding **forces** or **seeds** a satellite binding; (c) whether a satellite's divergence is a hard failure or a recorded reconciliation; (d) how the documented `opencode.json` opt-out (VS Code-only satellite) interacts with propagation; (e) whether `wiki-writer`/`wiki-verifier` gain registry rows.
