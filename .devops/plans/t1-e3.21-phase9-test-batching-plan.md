# Backlog: T1-E3.21 - Phase 9 test execution has no batching pattern

## Theme-Epic: T1 - Parcel Pipeline Machinery, E3 - Concurrency & Sprint Lifecycle

**Discovered:** 2026-09-25, operator question — *"is there a scenario where satellites run their test suite in batches to prevent ~269 sequential files?"* The scenario exists in the satellite's own CI (e.g. vitest `--shard=i/N` + `--merge-reports`, Playwright shards, per-directory Jest globs) but the parcel machinery neither declares, documents, nor coalesces it. This item parks the machinery-side answer.

## Why the machinery is not already covering it

Phase 9 already runs **whatever Phase 5 declares**, so a satellite technically *could* name sharded commands today; nothing tells it to, nothing reviews that the partition is sound, and nothing coalesces across a batch. The gap is a missing pattern + a missing coalescing option, not a broken protocol — which is why this is parked `LATER`, not `NOW`.

## What a fix would touch (one of three shapes, Phase 3 ranks them)

- **A — pattern docs in the declaration surfaces (cheapest):** `ptp-high-visionary/SKILL.md` § Test Verification Plan gains the option to declare partitioned commands for large suites (sharded/affected/run-once only, per `Gate Invocation Hygiene`); `@test-and-deploy` § Unit & Integration Tests gains the same one-liner; nothing scriptable changes.
- **B — machinery option in the batch path:** `@sprint-run` / `ptp-parcel-fast` accept a per-plan targeted-suite hint (derived from `touches:` paths) with the **full suite still running once per wave or per batch** — otherwise the AUTO positive-evidence contract and Gate D's "every command exits `0`" are weakened in silence. Touches `plan-lifecycle.md` § AUTO Gate Evidence Contract + the `sprint_eligible.py` advisory pattern (precedents: `T1-E3.19`/`T1-E3.20`).
- **C — portable walkthrough:** a short live-exercised example of declaring sharded commands inside one plan's Phase 5, vaulting the pattern heat the first satellite does this.
- Wrap-up carries one **patch** machinery-version bump from the live value (portable-surface change; single writer rule).

> **Decided write set (expansion ruling, 2026-09-26):** `plan-lifecycle.md` (§ Gate Invocation Hygiene suite-scope clause — the only statement), `ptp-high-visionary/SKILL.md` + `ptp-code-surgeon/SKILL.md` (declaration + execution), `template-plan.md` (Phase 9 scope recording), `sprint-run/SKILL.md` + `agent-wrap-up/SKILL.md` + `test-and-deploy/SKILL.md` (one reporting/naming line each — `@test-and-deploy` behavior unchanged), `version-history.md` (the wrap-up's release row). `ptp-parcel-fast` stays off (inherits the surgeon); no script, no manifest, no shared-prefix edit — SKILL bodies only, the embeds regenerating via `check-parcel-prefix.ps1 -Sync`.
