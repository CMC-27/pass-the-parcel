## 1 Phase 1: Expansion & Scoping
**Skill Executed:** `ptp-context-hunter`

**Intent:**
The operator loses track of a sprint's position mid-run: every batch moment speaks its own dialect ("fork", "yield", "lane readout", "fixpoint") and its own page shape, so the eye re-learns the view every time. Deliver **one queue dashboard** — a plain-language, state-derived snapshot in the operator's sketched shape (sprint header → sprint start → one row per plan with a you-are-here marker → user testing → sprint close), rendered by a read-only script from live state, printed at every transition on the batch path, and adopted by `@sprint-status` so the human and the host read one shape.

**In Scope:**
- `scripts/sprint_dashboard.py` (NEW) — read-only renderer; imports `compute()` from `sprint_eligible.py` (that file is never edited), takes queue order from the sprint.md Committed Scope table (Q1), renders plain-text default + `--json` / `--yaml` data modes for the skills; writes nothing, decides nothing.
- `scripts/tests/test_sprint_dashboard.py` (NEW) — fixtures driving the real CLI in temp trees (the test_sprint_eligible.py pattern), pre-fix probe of a rule cited from Phase 1 recorded.
- `sprint-run/SKILL.md` — § 1 step 7 preview opens with the dashboard; § 3 narrate-one-line → dashboard at each transition + the `your-move` card on a deferral halt; § 6 reports open with it; § 7 one cadence line. No branch/preset/deviation changes.
- `parcel-sprint.agent.md` — § Workflow step 4: the one-line narration upgrade, minimal edit.
- `sprint-status/SKILL.md` — § 4 + its example block adopt the dashboard (one format, two entry points); version + `updated` bumped (repo convention, per Q4).

**Out of Scope:**
- The eligibility predicate, lanes, fork branches, batch preset: unchanged — `sprint_eligible.py` is imported, never edited; the dashboard forces no branch.
- No defer/claim persistence — stateless; every print re-derives from live files (Q3).
- No new CI step or gate; no `validate.yml` change; no new lifecycle state or claim-status value; § Deviations stays at exactly three.
- `parcel.agent.md`, the six `ptp-*` agents/skills, `base-context.md` + seed: untouched (existing handoff cards carry the print duty — no new spawn vocabulary).

**Perimeter Notes:**
- **View, not state:** renders `claim_status` + bottom `Status` + `SPRINTS.md` + the sprint.md table order; never a source any agent reads back for decisions — a parser of the dashboard prose is a defect (the data modes exist so consumers read data, not prose).
- **One home per piece:** format + badge map home in `sprint-status` § 4; print cadence homes in `sprint-run` § 3; the owner-facing rule ("dashboard-first for owner-facing batch text") homes in the new `.devops/rules/queue-dashboard.md`.
- Degradation honesty: no ACTIVE sprint, empty queue, or unparsable plan renders what state says in one line — the viewer reports reality, never halts machinery (`exit 0` + note; `exit 1` only for a named data failure).
