## What the fix does (operator-authored intent)

New step in `@sprint-close`, **before** the business-report step (E3.12) so the report can credit passed testing:

1. **Surface the test queue.** Collect candidate manual tests from each executed plan's acceptance criteria + Phase 10 tweak notes (the same sources Gate D sign-off reads), consolidated into one sprint-wide testing menu grouped by outcome/theme, not parcel code.
2. **Walk the tests one-by-one via the ask-questions tool.** Each test presented with what to do, what to expect; the operator reports pass/fail/blocked per question — the exact interaction shape in `@q-and-a` / `@true-or-false` (one call per question where the ask surface is single-question, one batched call where it accepts an array; the final confirse validation question always on its own per the T1-E3.08 pattern).
3. **Record the verdicts.** Outcomes land in the sprint folder (e.g. `user-testing.md`) alongside `sprint.md` so Step 6's archive moves it, and failed tests add actionable rows to the backlog or business report rather than evaporating.

## What a fix touches

`.devops/skills/sprint-close/SKILL.md` (new step + renumber + register/archive linkage), `.devops/templates/sprint.template.md` (`user-testing.md` row), `HOW-TO.md` (one mention). Cites — never restates — the ask-tool questionnaire mechanics from `@q-and-a` (`surface-budget.md`).
