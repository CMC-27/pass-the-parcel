## 1 Phase 1: Expansion & Scoping
**Skill Executed:** `ptp-context-hunter` (`SINGLE`: inline)

**Intent:** Close the two transport-completeness findings from the sync audit — numbered F8/F9 in continuity with the F1–F7 batch closed by `T1-E2.03` — so that "sync architecture" delivers everything the `.devops` machinery documents.

**In Scope:**
- **F8 — a new agent key never reaches a satellite's `opencode.json`.** `sync-architecture.ps1` `Update-TargetModelBindings` step 3 rewrites `model` values only for keys already present in the target's `agent` block; a key it lacks prints `BINDING-SKIP <key> (no agent entry in target opencode.json)` and the satellite's own `check-parcel-prefix.ps1` then fails (`opencode.json: no agent entry for registry key '<key>'`, `check-parcel-prefix.ps1:340-345`), failing the whole sync (exit 1). The agent **file** lands (`.devops/agents` is a portable dir) but the runtime never mounts it — `opencode.json` is the mount surface, not the directory. Reproduced in this session against a simulated pre-`parcel-sprint` satellite: `SYNC_EXIT=1`.
- **F8 contract clause:** the current behaviour is a **recorded `ponytail:` ceiling with a named upgrade path**, not an oversight — `.devops/archive/t1-e1.03-model-binding-propagation-plan.md:276`: "sync stamps only keys already present in the target's `agent` block. Ceiling: a satellite with a missing key is reported (`BINDING-SKIP`) and its validator FAILs — sync never adds or restructures repo-specific JSON (each satellite's `permission` blocks legitimately differ). **Upgrade path: a documented seed-block merge if the fleet ever needs unattended convergence.**" This plan is that fleet need arriving; the ceiling, its rationale, and the new semantics must be reconciled in one voice across every surface that states them (`sync-architecture.ps1` header + inline comment, `.devops/skills/sync-architecture/SKILL.md:70-74`, `.devops/rules/agents-and-skills.md:59`, `.devops/skills/model-routing/SKILL.md:71`).
- **F9 — `.devops/plans/template-plan.md` is not on the portable surface.** `portable_dirs` correctly omits `.devops/plans/` (it holds claimed plans) and no `portable_files` entry exists, yet the file is hard-referenced by the machinery a satellite receives: the **shared prefix** `base-context.md:53` (inlined into all 12 agents), seed `base-context.template.md:65`, `AGENTS.md:9,67` + seed `AGENTS.template.md:22,59`, `.devops/rules/plan-lifecycle.md:48`, `.devops/README.md:20`, and five shipped skills (`pass-the-parcel:215,287`; `ptp-context-hunter:26`; `spaghetti-monster:33,112,242`; `true-or-false:274,331`; `q-and-a:181`). A fresh satellite gets "instantiate from the canonical template" with no template.
