## 1 Phase 1: Expansion & Scoping
**Skill Executed:** `ptp-context-hunter`

**Intent:**
Make **"one session owns the plan"** an explicit, unambiguous rule on every live surface — and back it with a deterministic check — so no agent can again hand the operator an *"open a fresh session / say continue"* baton between phase groups.

**The defect this closes.** `T1-E4.02` (closed 2026-09-18 as "resolved by direct fix", commit `e80950e`) **removed** the session-rotation wording but never **stated the positive rule**. Three live docs still carry the old phrasing, and the canonical skill says only *"delegates one phase grouping at a time"* — which reads either way. Result: on 2026-09-19 the `parcel` orchestrator, running `T1-E1.04` (`SINGLE`), wrote a `> **Next session …**` baton into the plan's own State & Gates and ended the turn. On 2026-09-19/20 it happened again on the same plan: Phases 4-7 were written, Gate B was auto-cleared **in the body**, the bottom dashboard was left at `PHASE_3`, and the run asked for a new session. The work was correct; the handoff was not.

**Why it recurs.** "Strict Context Isolation" was built to mean the **sub-agent's** cold context (it reads the plan and exits). It was restated as **one phase-group per user session**, and that reading survived the `e80950e` sweep in three files. A model that reads the surviving fragments reconstructs session rotation. Nothing forbids a baton note, so the note becomes the instruction on the next turn.
