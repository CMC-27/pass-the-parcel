# Backlog: T1-E2.09 - Satellites are told to bump a counter they do not own

## Theme-Epic: T1 - Parcel Pipeline Machinery, E2 - Governance & Transport Integrity

**Discovered:** 2026-09-25, operator report — *"satellites are creating unintentional drift, thinking they need to increase machinery versions."* Grounded by [`../../audits/grid-link-field-audit-2026-09-24.md`](../../audits/grid-link-field-audit-2026-09-24.md) finding 4. Directly downstream of `T1-E2.08`, which made the divergence *loud*; this item is the missing half — stopping the divergence at its source.

## Findings

| # | Gap | Evidence | Impact |
|---|---|---|---|
| 1 | **The instruction travels; the carve-out does not.** `.devops/rules/` is a `portable_dirs` root (`.devops/sync-manifest.yaml:54`), so `agents-and-skills.md` ships to every satellite — and its § Sync Protocol states the bump step **unconditionally**: *"`@agent-wrap-up` bumps … `machinery-version` (scripts/agents/rules) whenever a portable file changes … No bump → satellites see DRIFT instead of UPGRADE."* | `.devops/rules/agents-and-skills.md:62` (also `:59`, which still calls the counter *"One integer"* — stale since the tiered scheme) | **Both clauses are false in a satellite.** A satellite's bump cannot cause a DRIFT/UPGRADE verdict for the transport set (sync stamps the source value over it), so the agent complies with a rule that can only harm — the exact generator of the reported drift. |
| 2 | **The truth lives on non-portable surfaces.** *"template-owned and sync-stamped: a satellite never bumps it"* exists in `.devops/logs/version-history.md:14` (a log — not in `portable_files`), `sync-manifest.yaml:23` (the manifest itself does not transport), `README.md:81`, and `HOW-TO.md:154` — where the bump sentence is again unconditional. | Those four paths are absent from `portable_files` / `portable_dirs`; only `agent-wrap-up/SKILL.md` (portable, `:169`) states the carve-out — as a **trailing clause after the instruction**, easy to read past. | The satellites that drifted did not ignore the rule; they followed the only version of it that reached them. |
| 3 | **The field proves it.** A live satellite reached counter **78** against the template's **72** with **zero** `machinery-version:` rows in its release log, and `-Check` reported the divergence as `UPGRADE` — an equality-only comparison that could not tell *behind* from *ahead*. | GRID-Link field audit, finding 4 | An inert, unrecorded bump became a counter the pull would silently rewind. `T1-E2.08` fixed the *detection*; nothing yet tells the satellite it is not the writer. |
| 4 | **The remedy is described where the culprit cannot read it.** The `AHEAD` halt already prints a correct reconcile recipe, but nothing in the portable surface says the commonest `AHEAD` cause is a bump the target should never have made. | `scripts/sync-architecture.ps1:476` (*"confirm the target has no release rows in the diverged range, then write `$srcMachV` into its manifest by hand"*) | A satellite hitting `AHEAD` reconciles by hand each time instead of never bumping; the loop repeats on the next session. |
| 5 | **Rule fan-out is unmeasured.** The counter's ownership rule has no row in the surface-budget registry, so Managed Simplicity's own instrument cannot see six surfaces restating (or omitting) it. | `.devops/rules/surface-budget.md` + `scripts/rule_fanout.py` (report-only) | The 2026-09-16 fan-out lesson applies verbatim: a rule with no registered home is re-authored per surface and each copy can drift independently. |

> Findings 1–2 are one defect seen from both ends: **the portable surface is the only surface a satellite obeys, and it carries the wrong rule.**

## Why the mechanism did not catch it

`T1-E2.08` hardened the *convergence* (behind `UPGRADE` / ahead `AHEAD` / shape crossing `MIGRATION`, the last two halt-and-reconcile) so a counter the target "earned" is never silently rewound — correct, and it is what surfaced this field evidence. But the design assumed a target could legitimately earn a counter. It cannot: the transport set is not the satellite's to version. `AHEAD` is therefore a **symptom**, and the treatment is upstream of the halt.

## What a fix would touch

- `.devops/rules/plan-lifecycle.md` § Claim Protocol → *Counter Ownership* — the canonical **portable** home: state ownership first (template-owned, sync-stamped; a satellite is never a writer), then the writer/monotonicity rules.
- `.devops/rules/agents-and-skills.md` — rewrite the two Sync Protocol bullets so a satellite reader is told the truth and **cites** the canonical section instead of restating the bump (the cite-once shape of `T1-E4.01`); fix the stale *"One integer"* description while in the file.
- `.devops/skills/agent-wrap-up/SKILL.md` Phase 7b item 2 — invert the envelope: *template repo only* becomes the gate around the bump, not a clause after it.
- `.devops/templates/SPRINTS.template.md` — the batch-bump sentence gains the same ownership qualifier.
- `HOW-TO.md` § 6 (template-side, but the maintainer reads it) — same correction, so the drift is not re-authored here.
- `.devops/skills/sync-architecture/SKILL.md` + the `AHEAD` message in `scripts/sync-architecture.ps1:476` — name the commonest cause: a satellite-side bump is inert and is stamped back down; reconcile by hand-writing the source value.
- `.devops/rules/surface-budget.md` — register the counter-ownership rule so `rule_fanout.py` measures it (report-only, never a second gate).
- Wrap-up: `.devops/sync-manifest.yaml` + `.devops/logs/version-history.md` — the fix is a portable-surface change, so one **patch** bump and its release row (the counter's single writer, per `@agent-wrap-up` § Batch Scope).

## Open questions for Phase 3

- [ ] One canonical statement plus citations (Managed Simplicity), or explicit prose in each portable surface? The fan-out metric says cite-once; a satellite agent that never followed the citation would still misread — which argues for one short ownership sentence **and** the cite.
- [ ] Does **release B** (the dotted flip to `1.0.73`, a named `T1-E2.08` follow-up with no parked plan) fold in here — one release, one bump, one satellite-facing change to the counter's identity — or stay separate? Note: this is presently a named follow-up with **no plan file**.
- [ ] Is a deterministic check warranted (a fixture asserting no portable surface states the bump without the ownership clause), or is the surface-budget registration the right, cheapest instrument? Default answer: registration, no new gate.
- [ ] Does Phase 7b need a satellite-side branch that actively **refuses** and records a skip line, rather than relying on the reader noticing the envelope?

## Why NEXT

Field-proven, small text-bound write set, and it completes the release that just shipped: `T1-E2.08` made the drift visible, this stops it at source. It is a reserved-surface parcel (the counter, the manifest, the release log) and edits the rules that govern its own execution, so it should run `MULTI`.
