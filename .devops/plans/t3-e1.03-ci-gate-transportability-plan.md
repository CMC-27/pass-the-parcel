2. **Composite action** — self-contained, but implies a second repo or a branch convention.
3. **Documented wiring block** in `SATELLITE-BOOTSTRAP.md` (the step the satellite pastes into its own CI) — zero transport machinery, zero enforcement (the status quo's honesty fix).
4. **Drift-job precedent**: `wiki-refresh.yml` is already transportable — does it already point the way?

`.github/workflows/` (the reusable surface, whichever fork wins), `.devops/sync-manifest.yaml` (`portable_files` — note `.github/workflows` is currently outside the walk by construction in the surface-budget report too), `SATELLITE-BOOTSTRAP.md` (the wiring step), `README.md` (scope the claim honestly or make it true).

## 1 Phase 1: Expansion & Scoping
**Skill Executed:** `ptp-context-hunter` (inline, `SINGLE`)

**Intent:** Make the advertised guardrails real in the field. The template's deterministic CI gates (`validate.yml`) stop at the repo border, so in a satellite the "deterministic guardrails" instrument is a local convention again — the exact failure it exists to prevent. Ship the **satellite-shaped invariant gate as a portable workflow file**, riding the transport surface that already carries `wiki-refresh.yml`, so it runs in every satellite on every push; scope `validate.yml` to what only the template can check; and correct the product-page claim so it describes what actually travels.

**Design fork ruling (Phase 3 decides — the smallest surface a satellite can adopt without restructuring its own CI):** **fork 4 — the drift-job precedent.** `wiki-refresh.yml` is already on the portable surface (`sync-manifest.yaml` `portable_files`), so a self-contained workflow file is a *proven* transport shape. A `workflow_call` reusable workflow (fork 1) couples every satellite to the template repo's CI at run time — a cross-repo dependency on a path and a ref, and a hard failure if the template is private or renamed. A composite action (fork 2) needs a second repo or a branch convention — more machinery than the problem. A documented wiring block alone (fork 3) is the status quo's honesty fix with zero enforcement, which is precisely what finding 7 is about. Fork 4 needs **no** new transport machinery and enforces for real.

**The split (ruling on the three Phase 3 open questions).** The gate list divides into:
- **Invariant everywhere** — runs in the satellite: parcel prefix integrity, UTF-8 agent encoding, wiki lint (guarded), claims coverage, claims drift. Each is a property of the *machinery or the content*, not of the template's identity.
- **Template-identity** — stays in `validate.yml` only: the transport `-SelfTest` (asserts the template's own portable-set mirror), the machinery-version discipline check (asserts the template's release log records its own counter — a satellite's release log is its own app-release series, never sync-stamped), and the fixture suites under `scripts/tests/` (not on the portable surface at all).

**In Scope:**
- `.github/workflows/machinery-gates.yml` (**new**) — the satellite-shaped invariant gate: self-contained, `push` / `pull_request` / `workflow_dispatch`, no `workflow_call`, no secrets.
- `.github/workflows/validate.yml` — header comment records the invariant/template-identity split (the split's single home) and points at the satellite subset. `validate.yml` remains the template's superset; its steps are otherwise unchanged.
- `.devops/sync-manifest.yaml` — `portable_files` gains the new workflow, with the reason stated inline; the `machinery-version:` value line is **untouched**.
- `.devops/templates/SATELLITE-BOOTSTRAP.md` — the "Your CI is yours to wire" note replaced by the truth: the gate arrives with the portable surface and runs on push. Front-matter `version: 14 → 15`, `updated:` refreshed.
- `README.md` — the "Deterministic CI gates" row made true and scoped to what travels; the transport self-test attributed to the template.

**Out of Scope:**
- **Forks 1 and 2** (reusable workflow / composite action) — rejected above with reasons.
- **Porting `validate.yml` itself**, or its template-identity steps, to the satellite gate — the three exclusions above are deliberate, not omissions.
- **Any change to the gate scripts** (`check-parcel-prefix.ps1`, `check-utf8-agents.ps1`, `wiki_lint*.py`, `wiki_claims.py`, `sync-*.ps1`) — the workflow *calls* them; it does not edit them.

Recorded, not worked around.

- **`sprint.md`, `agent-changelog.md`, `version-history.md`** — the batch wrap-up owns them.
- **The GRID-Link pull** — operator action (audit recommendation 1), not template work.
- **A `.wiki/` doc** — no wiki doc documents the CI/transport surface (recorded at Phase 4).

**Perimeter Notes:**
