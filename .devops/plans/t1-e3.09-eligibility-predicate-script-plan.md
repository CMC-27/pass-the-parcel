## 1 Phase 1: Expansion & Scoping
**Skill Executed:** `ptp-context-hunter`
**Intent:**
Extract the batch eligibility predicate into one canonical, tested script and make `parcel-sprint` **authoritative** on its output — eliminating the four-place prose duplication that has no executable test.

**In Scope:**
- New `scripts/sprint_eligible.py` (stdlib-only, flat front-matter parsing): dependency satisfaction (archive **or** `GATE_D_USER_APPROVAL`), `touches` normalisation + overlap, fixpoint iteration, queue-order claim order, skip reasons.
- New `scripts/tests/test_sprint_eligible.py` — a fixture table covering dependency chain, mutual cycle, overlap skip, satisfied-via-`GATE_D_USER_APPROVAL`, in-flight dependency, pre-existing `PHASE_9`, template exclusion, determinism, prefix overlap.
- A `validate.yml` CI step; `scripts/` entries added to `sync-manifest.yaml` portable_files; `machinery-version` bump + `version-history.md` literal.
- Canonical predicate statement in `.devops/rules/plan-lifecycle.md` § Claim Protocol; `sprint-run` and `ptp-parcel-fast` cite it rather than restating.

**Out of Scope:**
- Any semantic change to the predicate's rules.
- The concurrency scheduler — the script **emits parallel groups as data**, but T1-E3.11 consumes them.
- `@sprint-plan`'s mutual-overlap preflight (that is T1-E3.06 G2; this parcel supplies the tested predicate it will call).

**Perimeter Notes:**
- "Authoritative" is the point: on a script error the host **halts**, never silently falls back to reasoning from prose.
- The script must be deterministic and side-effect-free — it reads plan state, it never writes or claims.

**Current implementation (verified 2026-09-16):**
- The predicate is stated in **four** places: `plan-lifecycle.md` § Claim Front-Matter + § Deviations; `sprint-run/SKILL.md` § 2 (clauses 1–3, normalisation, queue-pairwise, fixpoint); `ptp-parcel-fast/SKILL.md` outcome map; `pass-the-parcel/SKILL.md` § Batch Runner. `sprint-run` and `ptp-parcel-fast` already carry an explicit "these two layers must not diverge" warning.
- **No test suite exists** (Sprint 8 retro: "Test count: **0 → 0**").
- Front-matter parsing precedent: `scripts/wiki_lint.py:66 parse_frontmatter` and `scripts/wiki_claims.py` — a hand-rolled "flat YAML subset" reader. The repo is stdlib-only for Python (no `package.json`, no `requirements.txt`).
- CI: `.github/workflows/validate.yml` (Python 3.12) runs the wiki scripts plus the machinery-version predicate — the manifest value must appear as a literal in `version-history.md`.
- `parcel-sprint` has `bash: "allow"` in `opencode.json`, so the host **can** run a script and act on its output.
- `T1-E3.06` **G2** is the same class of defect: an untested predicate committed a queue the batch could only run one wave at a time.

**Architectural considerations:**
- Making the script authoritative changes **how** `parcel-sprint` computes eligibility (shell out, act only on output, halt on error) — an architecture shift, not a lint.
- The script's `parallel groups` output is deliberately forward-compatible with `T1-E3.11`.
- Reuse over reimplementation: hand-roll the tiny front-matter + inline-list parser to match the repo's stdlib-only style rather than adding a YAML dependency for plan files.
