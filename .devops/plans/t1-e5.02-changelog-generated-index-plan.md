# Backlog: T1-E5.02 - The changelog becomes a generated index; plans are the source of truth

## Theme-Epic: T1 - Parcel Pipeline Machinery, E5 - Change-Scale Pathway & Records

**Discovered:** operator ruling 2026-09-24 ("the agent changelog eventually dies out, plans are our source of truth"), with field evidence: GRID-Link's changelog spans **8 days** (2026-09-16 → 09-23, 26 entries) while its plans span **months** (346 archived) — the field already converged on plans-as-record. See [`.devops/audits/grid-link-field-audit-2026-09-24.md`](../audits/grid-link-field-audit-2026-09-24.md).

## Findings

| # | Gap | Evidence | Impact |
|---|---|---|---|
| 1 | The Why is authored **three times** per change: the plan, the changelog entry, the version-history release row. | Template changelog entries vs archived plans vs `version-history.md` rows for the same parcels. | Triplicated authoring is exactly the restatement surface Managed Simplicity retires — and the field has already stopped paying it (GRID-Link's changelog is thin and recent). |
| 2 | The changelog has a second job that blocks simple deletion: AGENTS.md rule 5 / the PREFIX-LOCKED prefix ("read the last 3 entries") makes it the cold-start recent-state signal. | `AGENTS.md` rule 5; `.opencode/plans/base-context.md` Core Development Rules item 5. | Deleting it breaks the prefix rule — and editing the prefix is the serial-lane, 9-agent re-inline cascade. |

## Design (operator-ruled direction)

The changelog becomes a **generated thin index**: one line per change (code, date, one-line summary, plan link), written at wrap-up from the plan, **never independently authored**. Rule 5 survives untouched and gets cheaper — the payload changes, not the rule. The Why lives exactly once, in the plan. Full deletion can follow later if the index proves redundant; the index is the honest first death (it keeps the cold-start signal while killing the duplicate authoring).

## What a fix would touch

`.devops/logs/agent-changelog.md` (format conversion — index entries going forward; history rows stay, never retro-edited), `agent-wrap-up` SKILL (the writer step becomes the index step), possibly `version-history.md` (the release row slims to cite the plan code — **composes with T1-E2.08, which also touches it: sequence to avoid double-touching**).

## Open questions for Phase 3

- [ ] Index entry **authored by wrap-up** (the AUTO-contract presence precedent) or **generated by a script** from the plan (deterministic, but one more surface)?
- [ ] Does the version-history release row slim to a citation now, or is that T1-E2.08's territory (sequence the two parcels)?
- [ ] What is the migration line — index format from a fixed date forward, with the existing narrative rows preserved above it?

## Why LATER

Nothing is broken — the field shows the record survives without dense changelog entries. Valuable consolidation, sequenced behind T1-E2.08 (shared surface) and complementary to T1-E5.01 (micro plans slot straight into an index-shaped changelog).

## 1 Phase 1: Expansion & Scoping
**Skill Executed:** `ptp-context-hunter` (inline — `SINGLE`/`AUTO`)

**Intent:** Make the changelog a thin, honest **index** so the Why is authored exactly once — in the plan. Today a single change is written three times (the plan, the changelog entry, the version-history release row), and the field has already stopped paying it: GRID-Link's changelog spans **8 days** while its plans span **months** (346 archived). The changelog keeps its one load-bearing job — AGENTS.md rule 5's cold-start *"read the last 3 entries"* signal — but its payload changes from a 5-line narrative to a **one-line index entry** (date · code · one-line summary · plan link), written at wrap-up **from the plan**, never independently authored. The version-history release row slims to a citation of the plan code in the same pass. Rule 5 and the PREFIX-LOCKED prefix are **not touched**.

**In Scope:**
- `.devops/logs/agent-changelog.md` — a top orientation note + a labelled `## Index (2026-09-25 forward)` boundary block carrying the one-line format. Existing narrative entries are preserved **byte-identical** above the boundary (never retro-edited); new entries append at the end.
- `.devops/skills/agent-wrap-up/SKILL.md` — Phase 1 becomes the **index step** (one line per change, written from the plan, appended at the end); Phase 0 step 1's baseline discovery moves to `git log --oneline -1 -- .devops/logs/agent-changelog.md`; § Batch Scope's *"one changelog entry naming the theme"* becomes *"one index line per plan"*; Phase 7b step 3's ref record points at the plan link. Bump `version` 18 → 19, `updated: 2026-09-25`.
- `.devops/logs/version-history.md` — a **release-row format** rule in the strategy section: the `Key Release Highlights` cell cites the plan code(s) + a one-line summary + plan link; the Why lives once, in the plan. Existing rows preserved.
- The Phase 3.5 measurement: the changelog-vs-plan span evidence, read from the live file and the field audit.

**Out of Scope:**
- **No change to AGENTS.md rule 5 or the PREFIX-LOCKED prefix** (`.opencode/plans/base-context.md`, `.devops/templates/base-context.template.md`, `.devops/agents/*`). Rule 5 survives untouched — the payload changes, not the rule — so no `-Sync` cascade fires.
- **No generator script.** `scripts/` is untouched: a plan-parsing generator is a new surface with a new failure mode, and the wrap-up already has the context to write one line (Q1).
- **No bulk rewrite of existing changelog or version-history entries.** History is never retro-edited (`.devops/rules/process-lessons.md`; the version-history strategy's own one-writer framing) — the migration is prospective, from a labelled boundary.
- **No change to `@sprint-plan`, `@sprint-run`, `@sprint-close`, `plan-lifecycle.md`, `.devops/backlog/*` or `MATURITY.md`.** The T1-E5.02 backlog register row is the batch wrap-up's job.

**Perimeter Notes:** Machinery-only; no app source tree. **Why the index, not deletion:** the changelog's second job (rule 5's cold-start signal) is real, and its home (the prefix) is the expensive 9-agent re-inline cascade — so the honest first death is the duplicate *authoring*, not the file. **Why prospective, not a rewrite:** a bulk reformat of ~40 historical entries is a high-risk edit that buys nothing, because the field already reads plans as the record; the index pays off from the boundary forward.
