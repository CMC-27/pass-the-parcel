## 1 Phase 1: Expansion & Scoping
**Skill Executed:** `ptp-context-hunter`

**Intent:**
Add a **sprint batch runner** to the parcel machinery: a dedicated primary agent `parcel-sprint` + skill `@sprint-run` that walks the committed sprint queue and executes each eligible plan **one at a time in a fresh context**, by spawning a new subagent `ptp-parcel-fast` (locked `AUTO`+`SINGLE` preset) per plan. Each plan is claimed on the trunk, run Phases 1→9 with Gates A/B auto-cleared (C `N/A`), and left at `PHASE_9` with **Gate D `OPEN`** — deferred, not skipped. When the queue's eligible set is drained, the host emits one consolidated Gate D report so the user tests all changes once.

Design decisions locked interactively before plan instantiation:
- **Batched Gate D** — run all eligible plans to `PHASE_9`, one report, user tests once. (Documented deviation.)
- **Trunk-sequential** — no `git worktree` per plan; all changes land on one tree. (Documented deviation.)
- **Strict SINGLE per plan** — no `MULTI` escalation; stop-the-line on failure.
- **Per-plan subagent** — fresh context per plan; `parcel-sprint` is the task-allowed host.
