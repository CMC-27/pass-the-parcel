## 1 Phase 1: Expansion & Scoping
**Skill Executed:** `ptp-context-hunter`

**Intent:**
Give the batch host a **batch wrap-up**: after the consolidated Gate D verdict, confirm each batched plan's implementation, mark the plans complete, and archive the whole batch in **one coalesced pass** — instead of running the heavy per-plan `@agent-wrap-up` N times inline.

`@agent-wrap-up` is already session-scoped: Phases 0–3, 5, 6, 7a are "once per session" (its own rule: "multiple plans closed in one session get one entry naming the theme"). Only **Phase 4 (Plan Finalization)** is per-plan. So the fix is a **batch scope** on the existing wrap-up skill, not a second wrap-up source of truth. `parcel-sprint` runs it once and is permitted to spawn `wiki-writer` for the read-heavy wiki prose (user decision).

**In Scope:**

**D1 — Batch scope on `@agent-wrap-up`.** Accept an input list of plan codes (the sprint's batched plans at `GATE_D_USER_APPROVAL`). Phase 4 iterates over the list; every other phase runs once. Keep the single wrap-up contract (`agent-wrap-up` stays the only wrap-up owner). Add a `version:` bump.

**D2 — Confirmation gate (confirm before completing).** For each plan: assert bottom `Status: PHASE_9`, `claim_status: GATE_D_USER_APPROVAL`, a `DONE` per-plan outcome, Phase 9 verification evidence + acceptance criteria present, and its exact `plan: <code>` commit on the trunk. Then run the repo gates **once** for the batch (tests/lint/build, `check-parcel-prefix.ps1`, `check-utf8-agents.ps1`, `wiki_lint.py`, `wiki_coverage_check.py`). A plan failing confirmation is **excluded as carry-forward** — never marked complete. A red repo gate blocks the batch wrap-up.

**D3 — Complete + archive as a batch.** Set `claim_status: COMPLETE` + bottom `Status: COMPLETE` + a Completion Note per plan, then `git mv` each to `.devops/archive/` (root). No branch — trunk-sequential (there is nothing to merge/prune). One changelog entry, one `machinery-version` bump, one wiki reconciliation pass, one backlog sweep, one knowledge-consolidation run.

**D4 — Trigger is a follow-up step, not inline at Gate D.** `@sprint-run` ends at the consolidated Gate D report (testing can cross sessions; Gate D always halts for the human). After the operator's verdict, the batch wrap-up runs as a distinct invocation (operator-invoked, executed by `parcel-sprint` or the ordinary wrap-up path). Record the chosen command surface in `plan-lifecycle.md` § Deviations and `pass-the-parcel` § Batch Runner.

**D5 — Host spawn surface.** `parcel-sprint`'s `task` allow-list is currently locked to exactly `ptp-parcel-fast`. Add `wiki-writer` (already subagent-invocable per `AGENTS.md`) so the batch wrap-up can delegate the read-heavy wiki reconciliation; `opencode.json` + `opencode.template.json` updated. Nothing else gains a spawn right.

**D6 — Composition with manual wrap-up + sprint close.** Manual per-plan wrap-up stays valid and unchanged. `sprint-close` § 1 must treat any surviving `GATE_D_USER_APPROVAL` plan as **not complete** (verdict + wrap-up required) or as explicit carry-forward — never silently close over it.

**Out of Scope:**
- The status, predicate, and fixpoint runner (T1-E3.03 — hard dependency).
- Changing Gate D semantics, auto-clearing it, or advancing past `PHASE_9`.
- Removing or narrowing per-plan `@agent-wrap-up`.
- A second wrap-up skill (single owner: `@agent-wrap-up`).
- New CI workflow or test harness.

**Perimeter Notes:**
- **Depends on T1-E3.03** (`depends_on: ["T1-E3.03"]`): the batch scope identifies its targets by `claim_status: GATE_D_USER_APPROVAL`. E3.03 must be archived before E3.04 can be claimed — their `touches` overlap (`sprint-run`, `plan-lifecycle`, `pass-the-parcel`, `sync-manifest`, `version-history`, `HOW-TO`). This is expected and correct under the new predicate: E3.04's dependency satisfies when E3.03 is archived (not when it merely reaches Gate D), because the `touches` overlap blocks it until then.
- **`machinery-version` `44 → 45`** + a `version-history.md` row (CI gate).
- **Wrap-up is safety-critical** — the confirmation gate is not simplifiable: never mark a plan complete without evidence, never auto-clean a red tree.
