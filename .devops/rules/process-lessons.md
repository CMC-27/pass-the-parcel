# Process & Tooling Lessons

> **The exit door for machinery, process and tooling knowledge.** `.wiki/core/18-knowledge-capture.md` (KC) holds **app-domain** tribal knowledge only; a lesson about the parcel/sprint machinery, the dev toolchain, or docs tooling is captured and promoted **here** instead. KC cannot promote such entries anywhere (the wiki documents the app, not the machinery), so without this register they accumulate forever — a one-way ratchet.
>
> **Entry format:** `- **[YYYY-MM-DD] Short title** — the rule. *Do instead:* the fix (only when non-obvious).` Max 3 lines, terse and deterministic.
>
> **Maintenance:** this is a staging register, not an archive. Fold a matured rule into its owning skill or [`plan-lifecycle.md`](plan-lifecycle.md) and delete it here; review the register at **sprint close** and keep it under ~25 entries. New rules arrive by capture-time routing (`@knowledge-capture`) or promotion (`@knowledge-consolidation` Phase 6b).

## Parcel & Sprint Mechanics

- **[2026-09-27] A report-only instrument has no reader unless the run makes one — re-run it on your own diff** — `rule_fanout.py` is report-only by contract and always exits `0`, so a diff that restates a registered rule can raise the `unauthorised` count and nothing fails. *Do instead:* when a diff edits machinery prose governed by a registered rule, run `python scripts/rule_fanout.py` and read the **`unauthorised`** column before Gate D, and prefer citing a canon over restating its signature. *(`T1-E3.23`, Phase 9)*
- **[2026-09-28] A gate whose subject it cannot observe must fail open on the honest case, closed on the claim** — `scripts/closeout_check.py` was first specced to reject any record whose sha was not reachable from `origin`, which would have failed on **every** close-out: wrap-up runs *before* the push (`@test-and-deploy` § 5 owns that), so an unpushed trunk is the ordinary state, not a defect. *Do instead:* split the honest state from the claim — `unreadable — <reason>` exits `0`, and only a **colour** (`green`/`red`) that the remote cannot back exits non-zero. A gate that cannot observe its subject still has two jobs: never demand the unobservable, never accept an unbacked assertion. *(`T1-E2.12`, self-review `BLOCK-1` + Phase 9 `R5` — a BOM'd record fails closed, which is the same rule from the other side.)*
- **[2026-09-17] Never round-trip a file through PowerShell text cmdlets** — `Get-Content -Raw | Set-Content -Encoding UTF8` under PS 5.1 reads BOM-less UTF-8 as ANSI and re-writes it, mojibake-corrupting whole batches in one loop; the damage is invisible in an editor and only the byte guard sees it. *Do instead:* edit with the file tool, or write with `[System.IO.File]::WriteAllText($p, $t, (New-Object System.Text.UTF8Encoding($false)))`, then confirm with `scripts/check-utf8-agents.ps1`.
- **[2026-09-16] A register row reading COMPLETE is a claim, not a measurement** — a parcel recorded a deployed runtime upgrade COMPLETE; six days later the live platform reported the old runtime on all five functions. The parcel updated one of two declarations and the other one won at deploy time. *Do instead:* re-measure a deployed state from the live artefact rather than the declaration, and when two declarations exist for one setting, name the single owner instead of updating one and leaving the other to win. *(Routed from GRID-Link Sprint 8 close.)*
- **[2026-09-10] Verify a cleanup parcel's orphan premise before deleting** — a feature shipped *after* the backlog item was filed may have re-wired the "orphan". *Do instead:* re-grep the current import graph first; if the premise is stale the parcel is a no-op, not a deletion.
- **[2026-07-18] Unified refactor model** — test refactor and code refactor are one plan, one change; source-first refactors enable deeper test cleanup. Each plan declares source-refactor priority.
- **[2026-09-06] Parallel subagent execution needs an exhaustive data contract** — a milestone list vanished because it existed in a schema one pass owned but the shared data-point contract didn't enumerate it. *Do instead:* enumerate every user-template field before partitioning files, and gate the handback with a template→schema→form coverage check.
- **[2026-09-06] Farthest-evolved consumer wins** — when template and satellite diverge, port the satellite's battle-tested machinery back into the template; app-specific content stays in the consumer. No carve-out remains: agent models are inherited from the CLI selection, so the old binding exception has no subject.
- **[2026-09-06] Post-sync bookkeeping self-heals** — sync stamps the target manifest's `machinery-version:` in place when the target is **behind**; a target *ahead* halts-and-reconciles instead of being silently rewound (ordering-aware `-Check`); `-Check` hashes only agent-unique content (frontmatter stripped), so per-repo prefix regeneration never reports phantom `DRIFT`.
- **[2026-09-13] Transport completeness (F8/F9)** — the sync must materialise every reference it ships *and* repair every derived surface it owns. A path named by the shared prefix or a shipped skill is portable; a registry key missing from the target's `opencode.json` `agent` block is inserted whole from the target's own synced seed, so a newly shipped agent arrives runnable — while an entry the satellite authored is never restructured. Supersedes the `ponytail:` ceiling recorded in `T1-E1.03`.
- **[2026-09-04] Set-level agent versioning** — agents are versioned as a coordinated set via `machinery-version:` — no per-file `version:`; only skills carry per-file versions, because the sync drift checker reads those from `SKILL.md`. The canonical-home rule for either counter lives in [`plan-lifecycle.md`](plan-lifecycle.md) § Claim Protocol → *Counter Ownership*.
- **[2026-09-03] Measure, then optimize** — measure a gate's real cost and output *before* restructuring around an estimated token claim; the estimate has been wrong in both directions.
- **[2026-09-18] A derived projection needs an insert path, not just a rewrite path** - a sync that rewrites only the keys a target already carries silently fails to propagate template-side *growth*: a new key never arrives and the target's own gate fails naming it. *Do instead:* when reconciling a projection, insert absent keys too, and test against a target that predates the new key.
- **[2026-09-28] Revision sweeps cover evidence carriers, not just the cited surface** - a fix that changes behavior must sweep every text encoding the superseded behavior (Phase 3 auto-resolutions, test-proposal shapes, AC probe wording), or the next review BLOCKs on two narratives for one finding (`T1-E3.24` N1: the canon was fixed, Q1/TP1 still mandated the old contract - one wasted reviewer round). *Do instead:* disposition the finding, then grep the plan for the superseded literals before declaring the round closed.
- **[2026-09-28] A declared `touches` answers "who may write this", never "when it may land"** - a `ptp-parcel-fast` runner legitimately declared `.devops/logs/agent-changelog.md` in its write set and staged it in its own `plan:` commit, landing it **before** the close-out gate pass - the one ordering the pinned green-stamp discipline forbids, so the changelog commit is no longer provably the post-pass closing commit. Nothing failed, because nothing checks it. *Do instead:* treat a **sequenced** surface (the changelog, the version row, any close-out artefact) as owned by the step that sequences it - a plan may write its own Phase 9 record, but the wrap-up owns the changelog's commit moment. `write_set_check.py` can only catch an **under**-declaration; an over-declaration is invisible to every gate, so the discipline lives in the plan author's head until `T1-E3.25` closes. *(`T1-E2.13` / `T1-E4.05` batch wrap-up; live instance recorded on `T1-E3.25`.)*

## Docs & Tooling

- **[2026-09-28] A guard that re-parses a candidate to judge it inherits the *host's* parser, so a lenient host makes it silently do nothing** — pwsh 7's `ConvertFrom-Json` accepts a comma left dangling before a closing brace that PS 5.1 rejects, so the engine's config write-guard shipped an unloadable `opencode.json` on Linux while the Windows-local run stayed green and the red sat on the trunk for four days undetected (the `v0.3.17` pattern recurring). *Do instead:* pair every such verdict with a host-monotone, string-aware scan of the text the edit itself produced (dangling comma, unbalanced braces) plus a permanent control on a **valid** config so "must never reject valid JSON" ships with an owner; and route every child the harness *judges* through one process-level capture that names the child and echoes its exit code and both streams, so a child failure can never masquerade as a behaviour assertion. *(T1-E2.11, Phases 8-9)*

- **[2026-09-25] Under `$ErrorActionPreference='Stop'`, PowerShell 5.1 makes a native command's stderr uncatchable — a `try/catch` around it gives a FALSE PASS** — a `try { & script } catch { … }` shape never fires, because PS 5.1 surfaces the native command's stderr as an error record **outside** the catch, so a negative fixture "passes" against a script that had in fact failed correctly. *Do instead:* assert a native command's failure through `Start-Process -RedirectStandardError` (then read the redirected stream and the exit code) — and treat any negative fixture you have never watched fail as unproven.
- **[2026-09-17] A walker's cost is path bookkeeping, not file I/O** — profiling `wiki_lint` on a 2100-doc satellite put **48%** of runtime in `Path.resolve()` (a syscall per link, per check), enumerated the corpus ~6× and read every doc 4-5× per run. *Do instead:* profile before optimising a walker, then make path identity syscall-free (`os.path.normcase(os.path.abspath(p))` under the repo root), enumerate each root once with directory pruning, and read each file once per run behind a cache — the same shape applies to PowerShell, where `Get-ChildItem -Recurse` loses to `Directory.GetFiles`/`EnumerateFiles`. Measured: `wiki_lint` 5,979 → 900 ms, findings byte-identical.
- **[2026-08-29] Vite 500 on a view = unresolved import, usually a missing `node_modules` package** — `net::ERR_ABORTED 500` loading a `.jsx` module is not a code bug when the editor is clean. *Do instead:* check `Test-Path node_modules/<pkg>`, run `npm install`, restart the dev server (Vite caches failed resolutions).
- **[2026-08-30] PowerShell writes BOMs and mangles inline Python** — `Set-Content -Encoding UTF8` emits a BOM that breaks frontmatter parsers; `python -c "…"` inside a quoted PS string corrupts or hangs the shell. *Do instead:* write probe/migration code to a `.py` file; read wiki files with `encoding="utf-8-sig"`.
- **[2026-08-30] Bulk frontmatter rewrites silently eat formatting** — a title-backfill normalised CRLF→LF, dropped the blank line before the H1, and produced backtick-quoted YAML titles the linter never caught. *Do instead:* after any bulk doc migration, diff-audit (`git diff --ignore-cr-at-eol`), restore blank lines, and scan for BOM/mojibake.
- **[2026-09-09] Long lines are truncated on read** — `read_file` truncates at ~2000 chars with a `[truncated]` marker, so editing a line you only saw truncated writes the marker into the file. *Do instead:* append to giant-line files via a temp file + `[IO.File]::AppendAllText($target, $entry, (New-Object System.Text.UTF8Encoding($false)))`; recover with `git checkout -- <file>`.
- **[2026-09-12] Claims sourced from claim-carrying docs restamp late** — `scripts/wiki_claims.py update` stamps docs in walk order, so a claim whose `source` is another doc that also carries claims records the source's *pre-restamp* bytes and reports `STALE` right after one `update`. *Do instead:* source the claim from a non-claim file, or run `update` a second time.
- **[2026-09-12] Auto-cataloguing ignores index column semantics** — `wiki_lint._fix_unindexed` (used by lint `--fix`) inserts `[name, description]` into the first two data columns, so on an index whose columns are not `Doc | Description` (e.g. an index using `Doc | Service | Description`) the description lands under the wrong header. *Do instead:* add the row by hand for non-standard indexes.
- **[2026-09-11] Editing a claim source invalidates other docs** — claims bind by whole-file sha256, so touching a widely-claimed file (`AGENTS.md` is claimed by two wiki docs) flips those docs to `STALE` even though they did not change; CI is the only signal. *Do instead:* after editing such a file, run `python scripts/wiki_claims.py update` before the coverage gate.
