## Operator rulings locked at intake (2026-09-24)

1. **3-level scheme, deterministic**: `major.minor.patch`; **first value `1.0.73`** — major 1 aligns with the existing `v1.0.0` tag era, patch 73 continues the count for human continuity.
2. **Bump rule is mechanical, from the diff**: patch = routine improvement (default); minor = a new capability surface (a path with no prior registry/manifest row); major = operator-contract change — the diff intersects the **reserved-surfaces set** that already exists in `plan-lifecycle.md` § Claim Protocol.
3. **Ceremony attaches to the level**: patch = one-line history row, no CHANGELOG entry, no tag; major = full row + CHANGELOG + tag. Old patch rows may later be compacted (the CI asserts only the *current* value is recorded) — this unblocks the deferred W3 length cap.
4. **Collapse the dual numbering**: the manifest value *is* the release-log Version column; one number, one writer, one check.
5. **Majors are mandatory satellite pull milestones** (the downhill half of the feedback loop).
6. **Migration in two releases**: release A ships a dotted-tolerant parser while the value is still an integer; release B flips the value. No satellite re-bootstrap; no misread window (an old `(\d+)` + `[int]` parser would truncate `1.0.73` to `1` silently).

## 1 Phase 1: Expansion & Scoping
**Skill Executed:** `ptp-context-hunter` (inline, `SINGLE`)

**Intent:** Make the machinery version one honest number. The counter becomes a tiered `major.minor.patch` with a deterministic diff-based bump rule; the sync comparison becomes **ordering-aware** so a target that is *ahead* halts-and-reconciles instead of being silently rewound (finding 4 is the live instance); the CI discipline check becomes exact-line anchored so `72` can no longer match `721`; and the dual numbering collapses — the manifest value *is* the release-log version, one number, one writer, one check.

**Migration staging (locked operator ruling 6) — two releases, this parcel is release A:**
- **Release A (this parcel):** ship the dotted-tolerant parser + the ordering-aware verdict + the exact-line CI check + the documented tiered scheme, **while the manifest value stays an integer**. The reason is mechanical, not stylistic: the script that runs during a satellite pull is the *satellite's own* (old) script, and its `Update-TargetManifestVersion` matches `(\d+)` and rewrites `\d+` — fed a dotted source value it writes `machinery-version: 1.0.73.0.73`. A dotted value must therefore never ride in the same pull that delivers the tolerant parser.
- **Release B (named follow-up, out of scope here):** flip the value to `1.0.73` — a one-line change, because release A makes every reader dotted-tolerant and makes a cross-shape comparison a halt-and-reconcile (`MIGRATION`), so no satellite misreads and none needs re-bootstrap.
