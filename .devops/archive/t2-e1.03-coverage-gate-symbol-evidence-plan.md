## 1 Phase 1: Expansion & Scoping
**Skill Executed:** `ptp-context-hunter`

**Intent:**
Deferred carry-over from T2-E1.01 (Gate A, Q6). `scripts/wiki_coverage_check.py` currently decides coverage by **filename substring** or parent-folder path: `covered()` returns True when `re.search(r"(?<![\w])" + re.escape(name), index_text)` matches anywhere in the domain index, or when the parent dir path with a trailing slash appears. Both are weak anchors — an index row that merely mentions the string satisfies them, and a renamed symbol inside an unchanged file is invisible to CI, so the wiki can silently drift when code changes shape but not name.

Upgrade coverage to **symbol-level evidence**: a source file is covered only when its domain index cites a symbol the file actually exports, **or** an explicit Grounded Claims binding (`claims: source: <path>#<symbol>`, shipped in T2-E1.01) ties a wiki doc to it. This template repo carries no `src/` tree, so the template path must stay a graceful no-op; the stricter rule activates in satellites that do.

**Pending Phase 3 Questions (orchestrator relays one at a time — never batched):**

> [x] Q1: **Evidence anchor definition — what makes a source file "covered"?**
> A file passes the gate when EITHER (a) its **domain index cites a symbol that the source file actually exports**, OR (b) **any wiki doc carries a `claims:` entry whose `source` path resolves to the file** (the `#symbol` fragment is trusted, not re-verified).
> - `(Recommended)` **Hybrid (OR):** index-symbol evidence OR a claims `source` binding. Keeps today's index rows working when they name a real symbol, and adds the claims escape hatch for files the index does not name.
> - **Index-symbol only:** ignore claims entirely; every file must have a real exported symbol cited in its domain index.
> - **Claims-binding required:** index text is never sufficient; a file is covered only by an explicit `claims: source: <path>#<symbol>` authored on some wiki doc.
> Trade-off: the hybrid honours both the existing index contract and the new claims layer and cannot regress satellites; index-only discards the layer shipped in T2-E1.01 and under-delivers the drift mandate; claims-required is the strongest evidence but forces every satellite file to be claim-annotated before its coverage gate can pass (large migration, likely red CI on upgrade).

> [x] Q2: **Implementation source of truth — consume the claims layer or parse index text only?**
> Should `wiki_coverage_check.py` **import `scripts/wiki_claims.py`** (reuse its parser; read `claim_docs()` and invert the doc→source map into source→evidence), or stay self-contained?
> - `(Recommended)` **Consume `scripts/wiki_claims.py`:** import the parser / `claim_docs()`; the index symbol scan stays local to the coverage script.
> - **Independent:** re-implement the minimal `claims:` reading inside `wiki_coverage_check.py`; no cross-module import.
> - **Claims as fallback only:** keep index-only for files that already pass; consult claims only for files that fail the index scan.
> Trade-off: importing honours T2-E1.01 F2 (single parser owner) and prevents shape drift, at the cost of a dependency chain (`wiki_coverage_check` → `wiki_claims` → `wiki_lint`); re-parsing duplicates the claims shape that F2 explicitly forbids; the fallback is zero-regression but makes coverage results path-dependent and harder to reason about.

> [x] Q3: **How is a "real symbol" discovered, given no JS/TS parser and a stdlib-only budget?**
> - `(Recommended)` **Regex export scan:** extract exported identifiers from the source (`export function|const|class|default`, `module.exports`, named export lists); an index token counts as symbol evidence iff it equals one of them.
> - **Trust the claim fragment:** when a claim supplies `path#symbol`, accept it without checking the symbol exists inside the file; index tokens stay unverified text.
> - **Symbol == file stem:** treat a file as symbol-covered when the index cites its exact stem (today's guarantee); require a claim for anything else.
> Trade-off: the regex scan is dependency-free and catches real renames for the common `export const X` / `function X` shapes, but is approximate for default exports, re-exports (`export { a as b }`) and anonymous JSX components — document that as a `ponytail:` ceiling; trusting the claim fragment is cheap but lets a stale/wrong `#symbol` pass; stem-equality is the most conservative and merely re-labels current behaviour (little drift protection).

> [x] Q4: **Backward compatibility for existing satellite indexes.**
> - `(Recommended)` **Additive:** existing filename/folder matches keep counting; symbol evidence is an additional pass route, so no satellite turns red on upgrade.
> - **Hard cut:** remove substring/folder matching; satellites must migrate their indexes to symbol anchors or their coverage gate fails.
> - **Opt-in strict flag:** default stays lenient; a CLI flag / config key enables the strict symbol requirement per satellite.
> Trade-off: additive keeps the "template behaviour must not regress" promise and allows gradual satellite adoption, but the gate still accepts weak evidence wherever the old rule already passes; hard cut delivers the drift guarantee immediately but breaks every satellite index on upgrade; a flag is flexible but silently ignorable, weakening the guarantee and adding config surface.

> [x] Q5: **Template no-op contract — keep as-is or add a regression guard?**
> The `src/`-absent path must stay green. Do we invest in an explicit regression check, or rely on the existing CI step + the early guard?
> - `(Recommended)` **Guard unchanged, no new test:** keep the `if not (ROOT / "src").is_dir(): return 0` early return as the first action in `main()`; CI already exercises it on every push.
> - **Guard + regression test:** also assert the no-op (e.g. `sync-architecture.ps1 -SelfTest` or a tiny smoke check) so a future refactor cannot break it silently.
> - **Docs-only hardening:** keep the guard and restate the contract in the script docstring + `SATELLITE-BOOTSTRAP.md`, no executable guard.
> Trade-off: the guard alone is the minimal change and the no-op is already CI-covered; a regression test hardens it but touches `sync-architecture.ps1` (outside the drafted affected-files list) and grows scope; docs-only records intent without a runtime guarantee. **Invariant regardless of choice:** the `src/` check must remain ahead of any claims loading so the template path never parses claims.

> [x] Q6: **Severity & `ALLOWLIST` — change anything?**
> - `(Recommended)` **Unchanged:** gaps stay `exit 1` (hard); the 5-entry `ALLOWLIST` with reasons stays; only *what counts as a gap* changes.
> - **Add a warn tier:** filename-only matches emit a warning (`exit 0`) while "no evidence at all" stays `exit 1` — migration telemetry.
> - **Claims-based exemptions:** replace `ALLOWLIST` entries with explicit reason annotations on the owning index.
> Trade-off: unchanged is the smallest surface and preserves the exit-code contract satellites depend on; a warn tier is friendlier for migration but weakens the hard gate and changes the contract; claims-based exemptions unify the mechanism but conflate "exempt" with "evidence" and need a new conventions decision.
