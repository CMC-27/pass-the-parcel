## 1 Phase 1: Expansion & Scoping
**Skill Executed:** `ptp-context-hunter`

**Intent:**
Harden the parcel blueprint itself. A full audit of `.devops/` and `.wiki/` (129 + 64 tracked files) found that the repo's own gates are green while several documented guarantees are false, two referenced artifacts do not exist, two referenced scripts never sync to satellites, and a dozen docs contradict the current implementation. Because this repo is the **template**, every false guarantee and portability hole is inherited by every satellite. This parcel makes the machinery's claims match its behaviour, closes the transport gaps, and removes the residue that de-contamination missed.

**In Scope:**
- **W1 - Linter truth & power** (`.wiki`): `wiki_lint.py` vs its documented check list; `--fix`; frontmatter-link validation; the "redirect log"; hardcoded exemption list.
- **W2 - Broken-reference repair**: the 7 unresolved `related-to` targets (6 files; count corrected at re-verification — `agents-and-skills.md` carries two); the phantom `Last Verified` column.
- **W3 - Transport / sync engine**: manifest completeness; cross-platform hashing; duplicate parsers; CI `-SelfTest`; `.vscode` portability; `.gitattributes` pins.
- **W4 - Template seed reconciliation**: `opencode.template.json`, `AGENTS.template.md`, `base-context.template.md`, `SATELLITE-BOOTSTRAP.md` vs live repo.
- **W5 - Doc truth sweep**: every stale/contradictory governance doc and skill/agent directive.
- **W6 - Version & log discipline**: `version-history.md` ordering + missing machinery-version; changelog gap; CI version check.
- **W7 - Dogfooding & residue**: sprint registers; placeholder backlog state; Gemini residue; duplicate slot-15 reference docs.
- **W8 - Model-binding truth**: retire mirror references; validate `opencode.json` model values; reconcile runtime vs registry.

**Out of Scope:**
- Any application feature work, `src/` tree, or `.wiki/` content outside the governance/examples docs named below.
- Re-binding models to different vendors (W8 only reconciles what exists; it does not choose new providers).
- Rewriting the parcel lifecycle, gate semantics, or the fixed 10-phase structure (only stale *descriptions* of them are fixed).
- Importing the full sprint cycle into this repo if the user prefers removal — W7 asks; it does not assume adoption.
- Redesigning `wiki_lint.py`'s architecture (extend/trim in place; no rewrite).

**Perimeter Notes:**
- This workspace has **no `src/` tree** — `wiki_coverage_check.py` no-ops by design. Keep that graceful no-op intact.
- Every changed file is portable machinery; **`machinery-version` must be bumped once** at wrap-up (see W6).
- **Single flight.** One working tree; W1 is a prerequisite for W2/W5 acceptance (the new lint check proves the fixes). Sequence accordingly.
- `AUTO` mode: Gates A-C auto-clear on mechanical verification; **Gate D always halts** for the human.
- Prefer **removing false claims** over building new machinery when the value is marginal (Simplicity Ladder). Implementing a check is only justified when a satellite genuinely benefits.
