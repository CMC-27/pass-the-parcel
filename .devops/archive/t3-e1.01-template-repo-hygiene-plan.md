## 1 Phase 1: Expansion & Scoping
**Skill Executed:** `ptp-context-hunter`

**Intent:**
Make this repository credible and self-explanatory as a public GitHub **template**. Today the flagship asset — the 10-phase parcel pipeline — is invisible from the front door: the root `README.md` is titled "Application Wiki", is 40 lines long, and never mentions the framework. There is no `LICENSE`, so nobody may legally "Use this template". There is no `CHANGELOG`, `CONTRIBUTING`, `SECURITY`, `CODE_OF_CONDUCT`, issue/PR templates, or worked example. Goal: a visitor lands, understands what this is in 30 seconds, legally reuses it in 5 minutes, and sees one complete worked run — while the existing deterministic gates stay green.

**In Scope:**
- **Legal:** `LICENSE` (MIT or Apache-2.0 — resolve at Gate A).
- **Community/health:** `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`.
- **Release surface:** root `CHANGELOG.md` + `.github/release.yml` + tag `v1.0.0`; keep `.devops/logs/version-history.md` as the internal machinery log (do not duplicate or replace it).
- **README rewrite** as a product page: brand name, one-line pitch, CI badge, mermaid of the 10-phase flow, "what you get" table, 5-minute quickstart (`Use this template` -> sync -> `/parcel`), feature matrix, repo map, links to `HOW-TO.md` + `SATELLITE-BOOTSTRAP.md`.
- **GitHub furniture:** `.github/ISSUE_TEMPLATE/` (bug/feature), `.github/PULL_REQUEST_TEMPLATE.md`, `.github/CODEOWNERS`.
- **Worked example:** promote a completed archived plan (candidate: `t1-e2.01-machinery-hardening-plan.md` + its `run-*/reviews/` + `decision_log.md`) into `.wiki/examples/` as an end-to-end walkthrough; fill `.wiki/examples/README.md` and `examples-index.md`.
- Docs sweep: update `AGENTS.md`/`HOW-TO.md` references if the README/quickstart introduces a canonical name or path.

**Out of Scope:**
- Any change to parcel phase/gate semantics or skill behavior.
- Wiki self-maintenance / claims / generation (tracked separately as **T2-E1.01**).
- Rewriting `.devops/logs/version-history.md` format — it stays the machinery release log with its CI-enforced discipline.
- Building a hosted docs site (possible follow-up; README-hosted mermaid only).

**Perimeter Notes:**
- **AGENTS.md machinery markers must survive.** `scripts/pull-architecture.ps1 -Verify` asserts markers in `AGENTS.md`; a README/AGENTS edit that removes them fails satellite verification. Run `-Verify` after any AGENTS.md change.
- README is repo-specific (not in `sync-manifest.yaml` `portable_files`), so rewriting it does not transport to satellites — confirm intent (template front door vs satellite front door).
- `LICENSE` is not in the portable surface; satellites choose their own. Decide whether the sync should *seed* a license (manifest change) or leave it repo-local.
- New `.github/*` files are not currently portable; if satellites should inherit PR/issue templates, add `.github` to `portable_dirs` — that is a `machinery-version` bump + `version-history.md` row.
- `.gitattributes` pins `eol=lf`; new Markdown/YAML files must be committed LF.
