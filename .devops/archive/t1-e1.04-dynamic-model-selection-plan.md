## 1 Phase 1: Expansion & Scoping
**Skill Executed:** `ptp-context-hunter`
**Intent:**
Stop shipping hardcoded default models, and let the operator choose subagent models *at run time* instead.

Two halves, deliberately separable:

1. **Remove the hardcoded defaults (the reversal).** Every binding surface stops naming a concrete model — the 11 agent frontmatter `model:` lines, the 11 `opencode.json` `agent.<key>.model` values, the `## Model Registry` model columns (live + seed), and the seed `opencode.template.json` values. With no binding declared, each agent inherits **the model selected in the CLI / picker**. Today the Model Registry flattens 11 rows to one identical model, so it buys no routing value while costing three mirrored surfaces plus a validation pass.
2. **Add run-time selection (the new capability).** Where a run actually spawns subagents, ask the operator which model each one uses:
   - **`parcel` in `MULTI`** — ask **per gate** (A / B / C / D) at plan start, defaulting to the CLI model.
   - **`@sprint-run`** — ask **one model for the whole batch** (each `ptp-parcel-fast` runs Phases 1→9 inline on a single model, so per-gate is meaningless there).
   - Record the answer in the frozen `Plan Settings` block (manual run) or the run report (batch), and pass it at spawn time **only on runtimes that support it**.

**Why this is a different route than `T1-E1.01`.** `T1-E1.01` (2026-09-03) introduced abstract capability slots; it was reversed on 2026-09-13 *because of complexity* — the binding machinery kept growing. This plan does not relocate that machinery, it **deletes** it. The complexity objection is answered by removal, not by a new home.

**In Scope:**
- Remove `model:` from all 11 agent frontmatter files (`parcel`, `parcel-sprint`, 7 × `ptp-*`, `wiki-writer`, `wiki-verifier`).
- Remove `agent.<key>.model` from `opencode.json` and from `.devops/templates/opencode.template.json`.
- Reduce the `## Model Registry` table (live + seed) to **key + capability class** — drop both model columns. The capability class is the one part still paying for itself: it feeds the run-time question's *recommendation*.
- **Invert** the model-binding pass in `scripts/check-parcel-prefix.ps1`: from "all surfaces agree on a model" to "**no concrete model binding exists** on any binding surface". Per Managed Simplicity the gate **moves — it is never deleted**.
- Remove the model-stamping pass from `scripts/sync-architecture.ps1`, and repair `-SelfTest` (the T1-E2.07 orphan-registry-row fixture is built on the 4-cell row shape).
- Rewrite the `@model-routing` skill: no registry binding source; the run-time selection procedure; model enumeration from the provider's `/v1/models` endpoint.
- Add the model question to `parcel`'s plan-start selection (`MULTI` only, skipped when `SINGLE` or when nothing is spawned) and to `sprint-run` § 1 preflight (before the single yes/no).
- Add a `Models` row to the `Plan Settings` block; have `ptp-parcel-fast` record the batch model it was handed.
- Correct the mirrored prose: `AGENTS.md` rule 9 + its seed mirror, `.devops/rules/agents-and-skills.md`, `HOW-TO.md`.
- Record the reversal in `.wiki/core/18-knowledge-capture.md` (the `Registry-canonical model binding` entry and the two `model bindings are the exception` clauses).
- machinery-version bump + `version-history.md` row + backlog register row.

**Out of Scope:**
- **The capability-class column** — retained. It is the recommendation input for the run-time question, not a binding.
- **Any capability-class → model policy or auto-recommendation engine.** The operator chooses; the system does not guess. No cost model, no scoring.
- **opencode spawn-time model override** — that is upstream (issue #6651, PR #11377, both open). opencode runs inherit the CLI-selected model; a requested override on that runtime is surfaced, never silently ignored.
- **Per-plan model choice inside a batch** — one model per batch, by operator decision.
- Any change to gate semantics, topology semantics, the lifecycle, or the batch eligibility predicate (`scripts/sprint_eligible.py` untouched).
- Satellite-side binding policy — with no binding to propagate, the question dissolves.

**Perimeter Notes:**
- **This reverses a recorded contract.** `T1-E1.03` (2026-09-13) made the registry the single source and force-stamped it, and its Phase 1 states that any reversal must be *"an explicit recorded decision, not an accidental drift."* The operator directed this reversal in writing on 2026-09-19; the `Selection record` above and the knowledge-capture amendment are that record.
- **The removal half invalidates a carved-out exception.** `18-knowledge-capture.md` twice exempts model bindings from "farthest-evolved consumer wins" (`:33`, `:58`). With no bindings, the exception has no subject and must be removed, not left dangling.
- **The validation gate must survive in inverted form.** A naive reading deletes ~150 lines from `check-parcel-prefix.ps1`; Managed Simplicity forbids that ("*a gate that must go is moved, not removed*"). The invariant genuinely still exists — it simply becomes "*no hardcoded model anywhere*" instead of "*all surfaces agree*".
- **Runtime asymmetry must be explicit, not blurred.** VS Code `runSubagent` gained an optional `model` parameter in **1.116.0** (VS Code issue #298380, closed); opencode cannot do it yet (#6651 open). The plan must not pretend the two runtimes behave alike.
- **`AUTO` + `SINGLE`** ⇒ no independent reviewer, Gates B+C merged, Gate C `N/A`. Operator-accepted (see `Selection record`).
- **Unverified assumption to settle in Phase 3:** this repo's `opencode.json` uses the **v1** schema (`agent` singular, `permission` object). The explicit "*inherits the parent session's model*" wording is from the **v2** docs; v1 describes `model` only as an "override". Removal of the bindings is only safe if v1 also falls back cleanly. This is the one hard blocker on the removal half.

### The three design decisions this phase settles

**D1 — The inverted gate's invariant.** The binding pass does not vanish; it inverts (`managed-simplicity.md:43` — *a gate that must go is moved, not removed*). The invariant becomes:

> **(G)** No binding surface declares a concrete model.

Concretely, all three must hold: (i) no `model:` key in any of the **11** binding files' YAML frontmatter; (ii) no `model` value under any `agent.<key>` in `opencode.json` or the seed config; (iii) every `## Model Registry` row carries **exactly two cells** — agent key, capability class — with no model cell present.

The third clause is what replaces the old "all surfaces agree" test: a 4-cell row is now the *failure*, not the requirement.

**D2 — The opencode override mechanism.** opencode cannot honour a spawn-time model (`#6651` open; Q9). Two candidate mechanisms were weighed:

| Option | Verdict |
|---|---|
| Pre-bound variant agents (one agent file per model) | **Rejected.** It reintroduces exactly the hardcoding this parcel deletes, multiplies agent files by the model count, and is the anti-pattern upstream names in `#6651` itself |
| Documented halt on an unhonourable override (Q7) | **Adopted.** The question is asked; if the answer is "inherit the CLI default" the run proceeds on any runtime; if the answer is a concrete override and the runtime cannot honour it, the orchestrator **halts with an explicit message** naming the runtime limitation and offering *proceed with inherit* or *run on VS Code* |

This keeps the edge case **accepted out loud** rather than engineered around.

**D3 — Where the choice is recorded.** `parcel` manual run → the frozen `Plan Settings` block gains a `Models` row. Batch run → the choice is recorded in `sprint_run_report.md` **and** handed to each spawned `ptp-parcel-fast`, which writes it into that plan's `Plan Settings` (the runner already owns that block as its first action). Single writer per surface; no second authority.

The `Models` row's three legal shapes:
- `CLI default` — inherit the model selected in the CLI / picker (the default when the operator declines).
- `per-gate: A=<model>, B=<model>, C=<model>, D=<model>` — explicit per-gate selection (`parcel` in `MULTI`).
- `N/A — no subagent spawns` — under `Agents: SINGLE`.

Gate→subagent mapping is taken from the existing delegation map, not redefined: **A** = `ptp-context-hunter` (+ `ptp-phase3-answerer` in `AUTO`), **B** = `ptp-high-visionary`, **C** = `ptp-grumpy-architect` + `ptp-smooth-operator`, **D** = `ptp-code-surgeon`. **Four questions maximum — per gate, never per subagent.**
