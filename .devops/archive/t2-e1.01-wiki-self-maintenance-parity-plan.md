## 1 Phase 1: Expansion & Scoping
**Skill Executed:** `ptp-context-hunter`

**Intent:**
Close the gap between this repo's **curated** wiki (human/agent-authored, linted, index-governed) and an OpenWiki-class **self-maintaining** wiki. The wiki is currently strong on governance and weak on truth-maintenance: no source-grounded evidence behind factual claims, no incremental refresh from code changes, no generation pass, no portable format, no publishable view. Target end-state: the wiki self-corrects when the codebase drifts, is refreshable from `git diff`, validates its format deterministically, and interoperates with OpenWiki (OKF) rather than competing with it. Differentiation stays on governance + the parcel pipeline; generation is borrowed.

**In Scope:**
- **Unified, versioned frontmatter** across all 60 `.wiki/**/*.md` docs (the repo currently carries two incompatible schemas — see Phase 2 §Forensic).
- **Grounded Claims layer:** every material proposition carries `source file#symbol` + content hash; a `scripts/wiki_claims_check.py` reports stale/retired claims when evidence changes.
- **Incremental `@wiki-update` skill:** map `git diff <last-verified-sha>..HEAD` -> affected docs (via index + claims) -> revise only those; stamp `last-verified`.
- **CI docs-PR job:** scheduled/`on: push` workflow that runs the update and opens a PR when the wiki drifts (mirrors `openwiki-update.yml`).
- **`@wiki-generate`:** source-reading generator that drafts hub/spoke rows and doc skeletons; demote `@wiki-bootstrap` to a verification pass.
- **OpenWiki / OKF interop:** ingest an `openwiki/` bundle (or emit OKF-compatible frontmatter) so a satellite can bring its own generator.
- **Publishable visualizer:** export the hub-spoke graph + a Markdown reader as a static site (GitHub Pages and/or MkDocs).
- Machinery bumps: skills (portable, auto-derived), `wiki_lint.py`, `sync-manifest.yaml` `machinery-version`, `version-history.md` row, `.github/workflows/`, `HOW-TO.md`, `AGENTS.md` task-lookup row(s).

**Out of Scope:**
- Rebuilding a full multi-provider documentation agent (13-provider matrix, Gmail/Notion/HN/X connectors). Use OpenWiki for that.
- Replacing `wiki_lint.py` — extend it, do not fork governance.
- Changing the parcel phase/gate lifecycle.
- `.wiki/rules/language/*` voice rules.

**Perimeter Notes:**
- Portable surface: new/extended skills sync to satellites automatically (derived: every folder in `.devops/skills/` minus `excluded_skills`). Non-skill changes (scripts, workflows, templates) require a `machinery-version` bump + `version-history.md` row or CI fails (`.github/workflows/validate.yml` version-discipline gate).
- Any change to `.devops/agents/*.md` must be re-inlined via `scripts\check-parcel-prefix.ps1 -Sync` and pass `check-utf8-agents.ps1`.
- `base-context.md` is PREFIX-LOCKED — never edit inline; edit `.opencode/plans/base-context.md` and re-sync.
- Claims frontmatter must remain `wiki_lint.py`-valid, or the wiki lint CI gate fails.
- `wiki_coverage_check.py` currently no-ops in this template (no `src/`). Claims work should not assume the coverage gate is active here — but must not break it in satellites.

**Spec Notes:**
- **Data flow (claims):** doc frontmatter `claims[].source` -> file on disk -> `sha256(file bytes)` compared to `claims[].hash` -> stale report on mismatch. No DB, no network, deterministic.
- **Data flow (update):** `git diff <sha>..HEAD --name-only` -> for each changed path, find docs whose `claims[].source`, `dependencies`, or `related-to` resolve to it -> revise those docs -> re-stamp `last-verified` + `claims[].hash` via `wiki_claims.py update`.
- **Data flow (generate):** `@wiki-generate` reads `.wiki/*-index.md` + source files -> drafts hub/spoke rows and doc skeletons -> `@wiki-bootstrap` verifies (no longer authors).
- **Data flow (interop):** `.wiki/**` frontmatter -> `wiki_okf.py export` -> OKF bundle (projection only; the local schema stays authoritative).
- **Data flow (visualizer):** `.wiki/**` links -> `wiki_visualize.py` -> `docs/wiki-graph.md` (mermaid) + catalog.
- **Edge cases the spec must cover:** doc with no `claims:` (legal — opt-in per material doc); `source` path missing (HARD); source file binary/absent; hash of an empty `claims` list; `format-version` on index/README (exempt files stay exempt); Windows/Linux path separators in `source` (store POSIX, `.gitattributes` pins LF); `docs/` is outside `.wiki/` so the wiki linter does not police it — the visualizer self-checks its own links.
- **Docs consumed by this feature (read-first list):** `.wiki/rules/frontmatter.md`, `.wiki/rules/link-hygiene.md`, `.wiki/rules/structure.md`, `.wiki/rules/document-structure.md`, `.wiki/core/17-docs-blueprint.md`, `.wiki/core/00-system-index.md`, `.wiki/core/18-knowledge-capture.md`, `.wiki/templates/README.md`.
