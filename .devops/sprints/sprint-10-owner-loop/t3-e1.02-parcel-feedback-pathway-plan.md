# Backlog: T3-E1.02 - Defined "parcel feedback" pathway: satellite agents push issues/improvements to the template backlog

## Theme-Epic: T3 - Template Distribution & Onboarding, E1 - Repository Hygiene & Presentation

**Discovered:** 2026-09-23, operator direction: "a defined pathway for 'parcel feedback' — an agent in a satellite can immediately push issues or improvements to the pass-the-parcel repo backlog for review. The context and detail comes with it, so we can triage these."

## Findings

| # | Gap | Evidence | Impact |
|---|-----|----------|--------|
| 1 | **Satellite→template feedback is conversational, not protocol.** The existing "fold candidates upward, do not edit locally" protocol (recorded via T1-E2.06, exercised by T1-E3.12) tells a satellite to *hold* improvements for the template — but there is no defined channel that moves the finding itself into the template repo's backlog with its evidence attached. | `@sync-architecture` skill + `.devops/README.md` transportability section; GRID-Link instances (T1-E3.12/13/14 all arrived by operator hand-carry, none by channel). | Each machinery lesson reaches this repo only when the operator remembers to relay it mid-conversation; context decays between the discovery moment and the write-down. |

## What the fix does (operator-authored intent)

A named, low-friction **parcel feedback** route:

1. **A `@parcel-feedback` skill** (or a scoped section in `@sync-architecture` — Phase 3 decides) that, when invoked in a satellite, drafts a parked plan **shaped for this template's backlog** — the existing parked-plan format (`type: backlog`, `claim_status: QUEUED`, Findings with evidence, What-the-fix-does, Open question) — from whatever context the satellite agent has in-session.
2. **Immediate push:** the draft lands where the operator can hand it to the template repo in one action — practically, a drop location (e.g. satellite-local `feedback/` outbox or a templated GitHub issues body via `gh`, per `@report`'s precedent) that the operator copies/commits without re-authoring.
3. **Intake side (template repo):** a short documented intake step — where landed feedback goes (`.devops/backlog/`), who/what triages it, what done-looks-like for "reviewed" — so arriving items never sit unaddressed.

## What a fix touches

New `.devops/skills/parcel-feedback/SKILL.md` (or `sync-architecture` extension), `HOW-TO.md` (one mention in the satellite workflow), `.devops/README.md` (Transportability paragraph). Portable-surface rules apply once it lives under `.devops/skills/**`.
