# Backlog: T1-E3.22 - The manual claim path has no enumerated green baseline

## Theme-Epic: T1 - Parcel Pipeline Machinery, E3 - Concurrency & Sprint Lifecycle

**Discovered:** 2026-09-27, during the `T1-E2.09` run — the trunk was **red on a CI step** the whole time, and nothing in the claim path would have said so.

## Findings

> The step that was red is **template-only** by design — `.github/workflows/validate.yml`'s header states the invariant-everywhere / template-identity split, and `machinery-gates.yml` carries the subset that travels. So the baseline question and the split rule are the same question.

## What a fix would touch

- `.devops/rules/plan-lifecycle.md` § Claim Protocol — one enumerated **green-baseline preflight** step for the manual path, stated once (the canon the batch path already cites in spirit).
- `.devops/skills/sprint-run/SKILL.md:18` (+ its `:85` halt list) — replace the two-script list with a **citation** of the canonical definition, not a second copy.
- `.devops/skills/pass-the-parcel/SKILL.md` § Claim & Pick-up Flow — the runner-side step that executes it.
- `HOW-TO.md` — the operator-facing claim walkthrough, if it lists the preflight.
- Possibly `scripts/` — a single `check-baseline` entry point if the definition is to be *run* rather than *read*; the `machinery-gates.yml` split rule decides which steps it may run in a satellite.

## Open questions for Phase 3

- [ ] Baseline = the **template's superset** (`validate.yml`, twelve steps) or the **invariant subset that travels** (`machinery-gates.yml`)? The template-identity steps assert template-owned artefacts and must not run in a satellite, so one answer cannot serve both.
- [ ] **A script or a documented command list?** A script is one home but risks a second dialect with the workflow; a list is a third copy. Is `gh workflow`/`act` in scope, or is the honest answer "run the workflow's own steps"?
- [ ] Does a manual-path preflight count as a **new gate** (the Q3-style objection: registration, not another gate) or as a **check of an invariant that already exists** and is merely unchecked today?
- [ ] Should a **red trunk stop the claim outright**, or be recorded and accepted like a red-baseline batch halt (`sprint-run` § 1 step 3)?
